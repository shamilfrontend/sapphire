# Режимы: Chat / Plan / Agent / Debug

В сайдбаре выбирается **ChatMode**:

| Режим | Tools | Назначение |
| --- | --- | --- |
| **Chat** (normal) | нет builtin tools | Диалог и codeblock’и; правки вручную через Apply |
| **Plan** | чтение/поиск + `create_plan` / `update_plan` | План в `.sapphire/plans/*.plan.md` без правок кода; «Сделать по плану» → Agent |
| **Agent** | все builtin (кроме `create_plan`) + MCP | Правки, терминал, web, memory, subagents, MCP; approvals |
| **Debug** | те же, что у Agent | Диагностика по runtime-трейсу: гипотезы → логи → минимальный фикс |

В Agent/Debug `update_plan` доступен только пока идёт сборка утверждённого плана. Полный список: [справка](/reference/tools).

## Когда что выбирать

- **Chat** — быстро спросить «что делает эта функция», получить сниппет и Apply вручную.
- **Plan** — сложная задача: исследовать → карточка плана → «Сделать по плану».
- **Agent** — реализовать задачу end-to-end.
- **Debug** — баг, причину которого нельзя уверенно назвать по коду: сначала трейс, потом фикс.

## Plan → Build

1. В **Plan** модель читает код и вызывает `create_plan` (файл в `.sapphire/plans/`).
2. В чате карточка: overview, **Открыть план**, **Сделать по плану**.
3. Файл `.plan.md` открывается в **Просмотре** (markdown без YAML). Переключатель **Просмотр / Markdown** — для правок исходника.
4. «Сделать по плану» переключает тред в **Agent** и запускает build; тогда модели доступен `update_plan` для прогресса todos.
5. На карточке виден текущий шаг (`2 из 4 · …`). Если ответ оборвался по лимиту длины, агент продолжает сам; когда продолжать нельзя — пишет открытый шаг.

## Debug

Те же инструменты, что у Agent (включая MCP), другой порядок работы:

1. Прочитать код и назвать 3–5 проверяемых гипотез.
2. Добавить минимальные логи или команду, которая их различит. Фикс на этом шаге не применяется. Логи — NDJSON в `.sapphire/debug.log` (не коммитить).
3. Воспроизвести. Если баг зависит от пользователя — остановиться и попросить воспроизвести.
4. По трейсу уточнить гипотезы.
5. Починить только подтверждённое трейсом; правка — самая маленькая верная.
6. Удалить инструментирование и `.sapphire/debug.log`.
7. В ответе: причина, доказательство и как проверить.

Очевидную опечатку можно чинить без трейса, явно сказав, почему он не нужен.

## Лимиты агента

Один запуск Agent/Debug: не больше **25** LLM-шагов; третий подряд одинаковый набор tool calls не исполняется. Остановка — сообщение в чате; следующий запрос пользователя продолжает с нуля.

## Approvals

В Agent и Debug IDE запрашивает подтверждение на edits / terminal / MCP, если auto-approve выключен. По умолчанию edits уже auto-approve; terminal и MCP — нет. См. [Tools](/guide/tools).
