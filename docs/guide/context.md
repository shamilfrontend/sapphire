# Контекст и @-упоминания

Модель видит не весь репозиторий целиком. Контекст набирается явно.

## Активный файл

По умолчанию при отправке сообщения в чат в контекст (блок `SELECTIONS`) автоматически добавляется **содержимое** файла из активного редактора — тот же формат, что у `@` / Ctrl+L.

В зоне вложений над инпутом это видно как чип с меткой **«Активный»**. Нажмите **×** на чипе, чтобы не прикреплять файл только в этот раз. Глобально отключается в Settings → «Автоматически прикреплять активный файл».

Строка `Active file:` в system prompt по-прежнему передаёт только **путь** (ориентация модели); содержимое идёт через SELECTIONS.

## Авто-поиск файлов (heuristic)

Если в сообщении мало явных `@` / вложений, при отправке клиент **эвристически** ищет релевантные файлы в workspace (по именам и содержимому через поиск VS Code) и добавляет до трёх в `SELECTIONS`.

В чате они помечены чипом **«Найдено»**. **×** на чипе исключает этот путь из авто-поиска на следующее сообщение. Отключается в Settings → «Автоматически находить релевантные файлы».

Не срабатывает, если уже прикреплена папка или ≥ 2 файла/выделения вручную.

## Staging selection

К сообщению можно прикрепить:

- **CodeSelection** — выделенный фрагмент в редакторе
- **File** — файл
- **Folder** — папка

Частый путь: выделить код → <kbd>Ctrl/Cmd</kbd>+<kbd>L</kbd> — выделение попадает в staging чата.

## @-упоминания

В поле ввода можно упоминать файлы и папки через `@`. Это добавляет их в контекст сообщения.

## Индекс проекта (`.sapphire/index`)

В фоне строится гибридный индекс workspace в `.sapphire/index/`: сначала локальный разбор (чанки, символы, `localRole`), затем опционально LLM-purpose через модель SCM, по одному файлу. В titlebar и композере режима Агент: статус «Проект проиндексирован» (клик — детали). Команда: `Sapphire: Reindex Workspace`. Каталог `.sapphire/index/` добавляется в `.gitignore`. Настройки: «Индексировать проект», офисные файлы, LLM-purpose.

Файлы, которые создаёт индексация:

| Файл | Зачем нужен |
| --- | --- |
| `manifest.json` | Метаданные индекса: версия схемы, время полной/инкрементальной сборки, счётчики файлов/чанков/символов/связей и прогресс LLM-purpose. По нему UI понимает, что индекс есть и насколько он актуален. |
| `files.jsonl` | Одна строка на файл workspace: путь, kind, hash, `localRole`, статус LLM и (если уже посчитано) `purpose` / `tags` / `whenUseful`. Основа поиска «какой файл подходит под запрос». |
| `chunks.jsonl` | Текстовые фрагменты файлов с якорем (anchor). Нужны, чтобы искать по содержимому и показывать релевантный кусок, не читая весь файл заново. |
| `symbols.jsonl` | Символы кода (классы, функции, методы…) с именем, kind и диапазоном строк. Нужны для поиска по API/именам сущностей. |
| `edges.jsonl` | Связи «файл → файл» (импорты и эвристики ссылок). Помогают понять зависимости и соседние файлы при поиске по проекту. |

Схема пайплайна и когда ходит LLM: [Индекс проекта](/architecture/project-index).

## Поиск по проекту

Пользователь **не выбирает** вариант поиска вручную и не вызывает эти tools из UI.

Два разных механизма:

1. **Авто при отправке** — [heuristic](#авто-поиск-файлов-heuristic): клиент сам может положить до 3 файлов в `SELECTIONS` (чип «Найдено»). Это не tool call.
2. **Во время ответа модели** — в режимах **Plan / Agent / Debug** модели доступен набор search/read tools (function calling). Какой tool вызвать (`grep_search`, `search_project_index`, …), **решает сама модель** по задаче; IDE только исполняет вызов. В **Chat** builtin tools нет — только то, что уже в контексте (`@`, активный файл, heuristic).

Ниже — что делает каждый tool, когда модель его берёт:

| Tool | Как работает | Когда модель обычно берёт |
| --- | --- | --- |
| `search_project_index` | Локальный token-score по `.sapphire/index`: path, purpose, tags, localRole, символы и чанки. Возвращает scored hits (~20 на страницу) с purpose/anchor. LLM на запрос не ходит. | Нужно понять, какой файл «про тему X» (в т.ч. офисные в индексе) |
| `search_pathnames_only` | Поиск VS Code только по **именам/путям** файлов (fuzzy `filePattern`), без чтения содержимого. Можно сузить `include_pattern`. | Известно имя или кусок пути (`AuthService`, `routes.ts`) |
| `glob_files` | Файлы по glob (`**/*.ts`, `src/**/*.tsx`). Пути с mtime/size, новее сверху; лимит по умолчанию 100. | Нужен набор по расширению/папке, а не fuzzy-имя |
| `grep_search` | Text-search по workspace: substring или regex, опционально include/exclude glob и case-sensitive. Отдаёт path + номер строки + текст строки (до 300 совпадений). | Вызовы, строки ошибок, точные идентификаторы |
| `search_for_files` | Тот же text-search, но возвращает **только пути** файлов с совпадениями (без текста строк). Можно ограничить папкой и regex. | Список файлов «где встречается X», без превью строк |
| `search_in_file` | Ищет substring/regex **внутри одного файла**; отдаёт номера строк. Для office — по извлечённому тексту. | Файл уже известен, нужно место в нём |
| `search_symbols` | Language service: классы/функции/методы по имени. Без `uri` — workspace symbols; с `uri` — outline одного файла. | Сущность по имени, файл ещё неизвестен |
| `go_to_definition` | LSP definition от файла + строки (+ опционально имя символа на строке). Путь, диапазон и one-line preview, не тело файла. | Есть файл/строка символа — прыжок к определению |
| `find_references` | LSP references (включая declaration), до 30 локаций с preview. | Call sites / usages известного символа |
| `get_diagnostics` | Error/warning маркеры языка и линтера: весь workspace или один файл. | После правок — где сломалось |
| `read_lint_errors` | Lint-ошибки **одного** известного файла (с короткой паузой на обновление). | Точечная проверка файла после edit |
| `read_file` | Содержимое файла (постранично / по строкам). Office → извлечённый текст, не сырые байты. | Прочитать найденный файл |
| `ls_dir` | Плоский список файлов и папок в каталоге (с пагинацией). Пустой uri — корень. | Обзор одной папки |
| `get_dir_tree` | Текстовое дерево каталога целиком. | Структура проекта/модуля |

В Agent/Debug дополнительно: `save_memory`, subagents, `web_search` / `browse_url` — см. [Tools](/guide/tools). Полный список и approvals: [Builtin tools](/reference/tools).

Соседние read-only tools из одного ответа выполняются вместе. Если тред не влезает в окно модели, при отправке старые результаты tools заменяются коротким пересказом (путь, запрос, код выхода). В чате полный текст остаётся; модели, которой нужно тело файла, сказано прочитать его снова.

## Сжатие длинного диалога

Когда оценка заполнения контекста достигает **~85%** окна модели (`CONTEXT_COMPACTION_THRESHOLD`), агент **автоматически** сжимает историю:

1. Старые сообщения (всё кроме недавнего хвоста) уходят в отдельный LLM-запрос без tools.
2. На их место в треде пишется одно сообщение «Сводка контекста» (`context_summary`).
3. Кольцо использования контекста падает; агент продолжает с summary + хвостом.

**Почему 85%, а не 100%.** Кольцо считает занятость относительно всего `contextWindow`. Сжимать заранее нужно, чтобы: (а) успеть сделать саммаризацию, пока ещё есть запас под сам запрос summary и следующий agent-turn; (б) не упираться сразу в жёсткий ephemeral trim/compact при отправке, когда диалог уже «под потолком». Порог 85% — запас ~15% до полного окна.

**Почему резерв ~16k под ответ.** У каждой модели в capabilities задан `reservedOutputTokenSpace` — токены, которые **не отдаём под вход** (system, tools, история), а оставляем под completion. Для `glm-5.3-flash` это **16 384**: длинные `rewrite_file`, build-скрипты и плотные agent-turn чаще влезают в один ответ. При отправке бюджет входа ≈ `contextWindow − reserved` (на кольце резерв показан отдельно: «Резерв для ответа модели»). У других моделей резерв свой (например 4 096 / 8 192).

Полный текст удалённых tool-результатов после такого сжатия в UI больше не хранится (в отличие от ephemeral digest при отправке). Повторное сжатие возможно, когда тред снова вырастет выше порога. Если саммаризация не удалась, остаётся прежний ephemeral trim/compact.

## Офисные файлы

К сообщению можно прикрепить `.xlsx`, `.xlsm`, `.docx`, `.pptx` и `.pdf` — в контекст идёт извлечённый текст. Полное описание форматов, tools, индекса и лимитов: [Офисные файлы](/guide/office).

## Copy Prompt из Explorer

В контекстном меню проводника есть действие скопировать содержимое файла/папки как prompt — удобно вставить в чат вручную.
