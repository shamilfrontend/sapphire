# Settings

Открыть: Command Palette → **Sapphire: Open Settings** (`workbench.action.openSapphireSettings`), либо иконка шестерёнки в UI.

Слева — вкладки меню. Ниже — по каждой вкладке, как в продукте.

## Провайдеры

У каждого провайдера свой ключ или адрес. После смены ключа список моделей обновляется.

См. [Онбординг](/guide/onboarding), [Ключ и ошибки](/intro/token-and-errors).

## Интерфейс

Карточки выбора layout:

| Режим | Что видите |
| --- | --- |
| **Режим IDE** | Классический редактор и чат справа |
| **Режим Агент** | Чат на весь экран: список диалогов слева, сообщение по центру |

Режим можно сменить и кнопкой в title bar. Подробнее: [Режим IDE / Режим Агент](/guide/agents-layout).

## Модели

Каталог моделей подключённых провайдеров. Тумблер **вкл/выкл** — доступна ли модель в выпадающих списках (чат, Apply и т.д.).

Это не выбор «какой моделью писать сейчас» в композере — только какие модели разрешены. Описание: [Модели и провайдеры](/intro/models).

## Опции

### Автодополнение

Экспериментально, только для FIM-моделей (код слева и справа от курсора).

- вкл / выкл;
- выбор модели с поддержкой FIM.

См. [Tab autocomplete](/guide/autocomplete).

### Apply

Настройки кнопки Apply:

- **Та же модель, что у чата** / отдельная модель;
- **Быстрый Apply** (блоки Search/Replace) или **Обычный Apply** (перезапись файла).

См. [Apply и diffs](/guide/apply).

### Инструменты

Функции, которые может вызывать модель; часть требует подтверждения.

| Пункт | Смысл |
| --- | --- |
| **Автоодобрение: правки** | Не спрашивать confirm перед edits (дефолт обычно вкл.) |
| **Автоодобрение: терминал** | То же для terminal (дефолт обычно выкл.) |
| **Автоодобрение: MCP** | То же для MCP tools (дефолт обычно выкл.) |
| **Автоодобрение: браузер** | То же для действий во встроенном браузере (дефолт выкл.) |
| **Исправлять ошибки линтера** | Передавать lint-ошибки в контекст агента |
| **Довести до зелёного** | Agent: после правок цикл diagnostics/тесты → fix; разово — `/verify` в сообщении |
| **Worktree для subagent** | Writable `run_subagent` → `git worktree` в `.sapphire/worktrees/` |
| **Автопринятие изменений от модели** | Сразу принимать diffs без ручного Accept |
| **Звуковой сигнал: окончание ответа и запрос подтверждения** | Звук в конце ответа / при approval |
| **Автоматически прикреплять активный файл** | Содержимое файла из активного редактора → контекст (чип «Активный») |
| **Автоматически находить релевантные файлы** | Heuristic: до 3 файлов по запросу (чип «Найдено») |
| **Индексировать проект** | Фоновый индекс `.sapphire/index/` |
| **Индексировать офисные файлы** | xlsx / docx / pptx / pdf в индексе |
| **LLM-описания файлов (purpose)** | Короткое «зачем файл» через модель SCM; очередь сама, когда в чате нет активных запросов |

См. [Tools](/guide/tools), [Контекст](/guide/context), [Индекс проекта](/architecture/project-index).

### Редактор

- **Показывать подсказки при выделении** — inline-подсказки при выделении в редакторе.

### Генератор сообщений коммита

- **Та же модель, что у чата** / отдельная модель для SCM commit-сообщений.
- В UI: панель **Source Control** (Activity Bar слева) — действие генерации сообщения; текст подставляется в поле коммита, его можно править перед commit.
- Нужны подключённый провайдер и git-репозиторий с diff.

## Правила

Правила задают постоянный контекст для модели (стиль кода, договорённости команды, запреты).

### Личные правила

Создавать, редактировать и удалять личные правила (+ New). Хранятся в настройках пользователя и подмешиваются в system / user context при сборке сообщения.

Готового корпоративного правила нет. Примеры своих правил: «Всегда отвечай по-русски»; предпочтения по Go / TypeScript; стиль коммитов.

Старое единое поле **AI Instructions** при обновлении становится первым личным правилом.

### Общие правила — `.rules`

Файл в корне workspace (кнопка **Открыть .rules**). Удобно коммитить в репозиторий.

Примеры идей: язык ответов; стиль PR/коммитов; запрет трогать директории; предпочтения по тестам и линтерам.

### Disable system message

Когда включено, в system message остаётся только то, что вы задали правилами выше (без встроенного system prompt продукта).

### Приоритет

Личные правила + общие `.rules`. При конфликте ориентируйтесь на более специфичные проектные `.rules` и явные указания в текущем сообщении.

## Скиллы

Скиллы — пошаговые инструкции для модели (code review, миграции, релизы и т.п.). В system message идут отдельным блоком `SKILLS` (правила — `GUIDELINES`).

По умолчанию в контекст попадает **каталог** (имя + краткое описание) и только **always-on** скиллы. Полное тело подгружается, когда в сообщении есть `/slug` (progressive disclosure).

### Личные скиллы

Создавать / редактировать / удалять (+ New). Хранятся в настройках пользователя. Включённый тумблер = always-on; выключенный доступен через `/slug`.

### Agent Skills (open standard)

В workspace подхватываются каталоги:

- `.claude/skills/<name>/SKILL.md`
- `.agents/skills/<name>/SKILL.md`

Формат: YAML frontmatter `name` / `description`, ниже — тело. В каталоге видны как `/name`; полное тело — после `/name` в чате.

### Общие скиллы — `.skills`

Файл в корне workspace (кнопка **Открыть .skills**). Короткий файл остаётся always-on; длинный попадает в каталог как `/workspace-skills` (алиас `/skills`).

### Приоритет

Always-on личные + короткий `.skills` + каталог дисковых/`/slug` + тела по `/slug`.

## MCP

MCP (Model Context Protocol) подключает **внешние tools** к режиму **Agent**.

- **Add MCP Server** — открыть конфиг (`mcp.json` / UI);
- список серверов, тумблер, статус / ошибки.
- Серверы поднимаются через channel на electron-main (`mcpChannel`).

### Когда доступны

MCP tools **не** доступны в Chat и Plan.

В Agent:

1. Модель видит каталог online-серверов и tool `enable_mcp_server`.
2. После `enable_mcp_server` полные схемы tools этого сервера попадают в контекст **текущего треда**.
3. Вызовы MCP проходят approval типа «MCP tools» (по умолчанию — ручной approve; см. **Опции → Автоодобрение: MCP**).

### Зачем

- доступ к внутренним API / тикетам / БД через корпоративные MCP-серверы;
- расширение агента без правки builtin tools в коде IDE;
- сторонние MCP (Playwright, Figma и др.) — на усмотрение разработчика; IDE их не блокирует.

Добавление своего сервера: [Extending → MCP](/extending/mcp). Builtin tools: [справка](/reference/tools). Трафик MCP: [Приватность](/guide/privacy).
