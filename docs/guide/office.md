# Офисные файлы

Sapphire умеет **читать** таблицы, документы, презентации и PDF в чате и через tools агента. В модель уходит извлечённый текст, не сырые байты архива.

Техническая схема разбора: [Архитектура → Офисные файлы](/architecture/office-extract).

## Чтение vs запись

| | Статус |
| --- | --- |
| **Чтение** | Есть: разбор OOXML/PDF → текст для чата, `read_file`, `search_in_file`, индекс |
| **Запись / правка «как Excel»** | Нет отдельного API: нет писателя настоящих `.xlsx` / `.docx` / `.pptx` / `.pdf` с сохранением стилей, формул и картинок |

Агент всё равно может **создать файл с расширением `.xlsx`** через обычные `rewrite_file` / терминал. Это не «офисная запись» продукта, а общий файловый tool: часто получается CSV/XML/скрипт под тем же именем, либо настоящий OOXML, если модель собрала ZIP через Python/`openpyxl` и т.п. Excel иногда открывает такой файл, иногда ругается на формат. Round-trip «прочитал xlsx → поправил ячейку → записал тот же xlsx» продуктом не гарантируется.

::: warning Будьте осторожны
Всегда **открывайте файл в Excel / Word / PowerPoint или PDF-ридере** и проверяйте содержимое, формулы и вёрстку, прежде чем опираться на результат или отправлять его дальше. Не считайте созданный агентом `.xlsx` валидным офисным документом, пока сами не убедитесь.
:::

## Поддерживаемые форматы

| Формат         | Что видит модель                                              |
| -------------- | ------------------------------------------------------------- |
| `.xlsx`, `.xlsm` | имена листов, размер, строки; даты из обычных числовых форматов Excel. Макросы не исполняются |
| `.docx`        | абзацы, заголовки, таблицы. Комментарии и правки не включаются |
| `.pptx`        | текст слайдов и заметки докладчика                            |
| `.pdf`         | текст по страницам                                            |
| `.csv`         | как обычный текстовый файл (без «офисного» разбора)           |

Не читаются: старые `.doc`, `.xls`, `.ppt` — сохраните их как `.docx` / `.xlsx` / `.pptx`. PDF без текстового слоя (скан) текста не даст: OCR нет.

## Как прикрепить к сообщению

Любой из способов:

- перетащить файл в панель чата;
- `@` и выбрать файл в workspace;
- открыть файл как активный (если включено авто-вложение активного файла);
- прикрепить папку, в которой лежат офисные файлы — при сборке контекста они тоже разбираются в текст;
- в Explorer: **Copy Prompt** — скопировать содержимое как текст для вставки в чат.

Во вложение к сообщению попадает **первая страница** извлечённого текста. Если файл длиннее, в Plan/Agent модель дочитывает его через `read_file` с `page_number`.

## Работа в Plan / Agent

| Tool             | Поведение для офиса                                      |
| ---------------- | -------------------------------------------------------- |
| `read_file`      | страницы извлечённого текста + оглавление (листы / число страниц или слайдов) |
| `search_in_file` | поиск по извлечённому тексту                             |

`edit_file` / `rewrite_file` пишут **текст** в путь, который вы укажете (в т.ч. `plan.xlsx`). Отдельного генератора валидного OOXML в IDE нет — надёжнее просить CSV/Markdown или проверить, что файл реально открывается в Excel.

Подробнее про tools: [Tools и approvals](/guide/tools).

## Индекс проекта

Если включены индекс и опция офисных файлов в Settings, `.xlsx` / `.docx` / `.pptx` / `.pdf` участвуют в фоновом индексе `.sapphire/index/` (чанки и, если включены LLM-описания, purpose — когда чат свободен). Тогда `search_project_index` может находить их по смыслу и тексту.

Настройки: «Индексировать проект», «офисные файлы», «LLM-purpose». Схема индекса: [Индекс проекта](/architecture/project-index), обзор в [Контексте](/guide/context).

## Лимиты и ограничения

- Файл **больше 25 МБ** не разбирается.
- Разбор локальный (main-процесс IDE); на шлюз уходит уже текст, как у обычных вложений.
- Нет гарантированного round-trip редактирования OOXML/PDF (см. выше).
- Нет распознавания сканов PDF.

## Типичные сценарии

1. **Спросить по таблице** — прикрепить `.xlsx` и задать вопрос; при длинном файле агент сам листает `read_file`.
2. **Сводка по презентации или ТЗ** — `@` на `.pptx` / `.docx` / `.pdf` в режиме Chat или Plan.
3. **Поиск по документам в репозитории** — включить индекс с офисными файлами, в Agent использовать `search_project_index` или явно `@` нужный файл.
