# Офисные файлы

Sapphire умеет **читать** таблицы, документы, презентации и PDF в чате и через tools агента. В модель уходит извлечённый текст, не сырые байты архива. `.pdf`, `.xlsx` / `.xlsm`, `.docx` и `.pptx` открываются во вкладке. PDF правится сборкой нового текстового файла. Таблицы, документы и презентации правятся на месте: стили, формулы и картинки остаются.

Техническая схема разбора и записи: [Архитектура → Офисные файлы](/architecture/office-extract).

## Чтение vs запись

| | Статус |
| --- | --- |
| **Чтение** | Есть: разбор OOXML/PDF → текст для чата, `read_file`, `search_in_file`, индекс. Скан PDF распознаётся локально (rus+eng) |
| **Просмотр** | `.pdf` — страницы и zoom. `.xlsx` / `.xlsm`, `.docx`, `.pptx` — вкладка: сетка, абзацы, слайды. Картинки на слайде показываются, формулы в ячейке видны как формулы |
| **Запись `.pdf`** | Есть: `edit_file` / `rewrite_file` собирают новый текстовый PDF из (отредактированного) извлечённого текста; исходная вёрстка и картинки не сохраняются |
| **Запись OOXML** | `edit_file` меняет текст в существующем файле: стили, формулы и картинки остаются. Смешанная раскраска внутри абзаца при правке этого абзаца схлопывается в первый фрагмент. `rewrite_file` собирает новый простой файл и старую вёрстку не хранит |

Клик в Explorer открывает `.xlsx` / `.xlsm`, `.docx` и `.pptx` во вкладке. Там можно править ячейки, абзацы и текст на слайдах; сохранение пишет изменения в тот же файл. Агент делает то же через `edit_file`. `rewrite_file` заменяет файл целиком простым документом без прежней вёрстки.

::: warning Будьте осторожны
После правок агента проверьте файл во вкладке. Сканы PDF без текстового слоя агент править не умеет. Полная перезапись через `rewrite_file` не сохраняет стили и картинки исходника.
:::

## Поддерживаемые форматы

| Формат         | Что видит модель                                              |
| -------------- | ------------------------------------------------------------- |
| `.xlsx`, `.xlsm` | имена листов, размер, строки; даты из обычных числовых форматов Excel; формула, если она есть в ячейке. Макросы не исполняются |
| `.docx`        | абзацы, заголовки, таблицы. Комментарии и правки не включаются |
| `.pptx`        | текст слайдов и заметки докладчика. Во вкладке ещё и картинки |
| `.pdf`         | текст по страницам; скан без слоя — локальный OCR; во вкладке — визуальный preview |
| `.csv`         | как обычный текстовый файл (без «офисного» разбора)           |

Не читаются: старые `.doc`, `.xls`, `.ppt` — сохраните их как `.docx` / `.xlsx` / `.pptx`. PDF без текстового слоя (скан) распознаётся локально, русский и английский, до 10 страниц. Правка такого файла через `edit_file` / `rewrite_file` недоступна: картинку нельзя собрать обратно из распознанного текста.

## Как прикрепить к сообщению

Любой из способов:

- перетащить файл в панель чата;
- `@` и выбрать файл в workspace;
- открыть файл как активный (если включено авто-вложение активного файла);
- прикрепить папку, в которой лежат офисные файлы — при сборке контекста они тоже разбираются в текст;
- в Explorer: **Copy Prompt** — скопировать содержимое как текст для вставки в чат.

Во вложение к сообщению попадает **первая страница** извлечённого текста. Если файл длиннее, в Plan/Agent модель дочитывает его через `read_file` с `page_number`.

## Работа в Plan / Agent

| Tool             | Поведение для офиса                                      |
| ---------------- | -------------------------------------------------------- |
| `read_file`      | страницы извлечённого текста + оглавление (листы / число страниц или слайдов) |
| `search_in_file` | поиск по извлечённому тексту                             |
| `edit_file`      | для `.pdf` — SEARCH/REPLACE по извлечённому тексту, затем новый текстовый PDF (вёрстка и картинки исходника не сохраняются). Для `.xlsx` / `.xlsm` / `.docx` / `.pptx` — та же замена по извлечённому тексту, но внутри существующего файла: стили, формулы и картинки остаются. Число листов, строк, абзацев и слайдов так не меняется |
| `rewrite_file`   | для `.pdf` — новый многостраничный текстовый PDF из `new_content`. Для `.xlsx` / `.docx` / `.pptx` — новый простой файл из того же вида текста, что возвращает `read_file`. Прежняя вёрстка не сохраняется |

Подробнее про tools: [Tools и approvals](/guide/tools).

## Индекс проекта

Если включены индекс и опция офисных файлов в Settings, `.xlsx` / `.docx` / `.pptx` / `.pdf` участвуют в фоновом индексе `.sapphire/index/` (чанки и, если включены LLM-описания, purpose — когда чат свободен). Тогда `search_project_index` может находить их по смыслу и тексту.

Настройки: «Индексировать проект», «офисные файлы», «LLM-purpose». Схема индекса: [Индекс проекта](/architecture/project-index), обзор в [Контексте](/guide/context).

## Лимиты и ограничения

- Файл **больше 25 МБ** не разбирается и не правится.
- Разбор, OCR и запись PDF локальные (main-процесс IDE); на шлюз уходит уже текст, как у обычных вложений.
- OCR скана — rus+eng, не больше 10 страниц. Хвост в контекст не попадает.
- Правка PDF с текстовым слоем через tools даёт новый текстовый PDF: исходные картинки и точная вёрстка не сохраняются. Скан (OCR) этими tools не пишется.
- `edit_file` для xlsx/docx/pptx не двигает картинки и не пересчитывает формулы. `rewrite_file` собирает новый файл без старых стилей и картинок.

## Типичные сценарии

1. **Спросить по таблице** — прикрепить `.xlsx` и задать вопрос; при длинном файле агент сам листает `read_file`.
2. **Сводка по презентации или ТЗ** — `@` на `.pptx` / `.docx` / `.pdf` в режиме Chat или Plan.
3. **Поиск по документам в репозитории** — включить индекс с офисными файлами, в Agent использовать `search_project_index` или явно `@` нужный файл.
4. **Поправить формулировку в PDF** — открыть `.pdf` во вкладке, в Agent попросить заменить фразу через `edit_file`; после записи preview обновится.
5. **Поправить ячейку, абзац или надпись** — открыть `.xlsx` / `.docx` / `.pptx` во вкладке и отредактировать там, либо попросить Agent заменить фразу через `edit_file`. Чистая вкладка перечитывает файл после записи агента.
