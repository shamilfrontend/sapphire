# Ключ и ошибки

## Где берётся ключ

Ключ выдаёт сам провайдер. Для DeepSeek это кабинет [platform.deepseek.com/usage](https://platform.deepseek.com/usage).

Обычно это Bearer `sk-…` в заголовке `Authorization`. У локальных серверов (Ollama, LM Studio, vLLM) часто достаточно endpoint.

## Где вводится

1. **Онбординг** при первом запуске — выбор провайдера и ключа или адреса.
2. **Settings → Провайдеры** — смена или очистка ключа.

При изменении ключа IDE заново запрашивает список моделей.

## Хранение

Ключ сохраняется **зашифрованно** (`IEncryptionService`). В открытом виде в настройках на диске он не лежит.

## Типичные ошибки

| Код | Смысл | Что делать |
| --- | --- | --- |
| **401** Unauthorized | Ключ отклонён | Обновить ключ в Settings или онбординге |
| **408** | Провайдер не успел обработать запрос | IDE повторяет запрос (с учётом `Retry-After`, до 3 попыток) |
| **429** RateLimited | Лимит запросов | IDE ретраит с `Retry-After`; затем подождать |
| Сеть недоступна | Нет доступа к API | Проверить адрес endpoint и сеть |
| TLS / сертификат | Не доверяем цепочке сертификата | Проверить системные CA |

Тексты подсказок живут в `llmProviderConfig.ts` (`LLM_ERROR_HINTS`) и обрабатываются в `sendLLMMessage.impl.ts`.
